# Figures

Every figure here is generated from a script in [`source/`](source/). The
rendered output in [`output/`](output/) is committed so the repository can be
read without running anything, but **the script is the source of truth**: fix
the script, rebuild, commit both.

## Rebuilding

From the repository root:

```bash
python figures/source/shewanella_oxa48_pathway.py
```

The scripts use the Python standard library only — no matplotlib, no network
access — and write SVG directly. Output is deterministic: rebuilding without
editing the script produces a byte-identical file, so a diff in `output/`
always corresponds to a diff in `source/`.

On Windows, if a script ever prints non-ASCII to the console, set
`PYTHONUTF8=1` first.

## What makes the output byte-identical

Two things, and both are load-bearing:

1. **The scripts write `newline="\n"` explicitly.** Python's text mode would
   otherwise translate newlines to CRLF on Windows, so the same script would
   emit different bytes on different platforms.
2. **`.gitattributes` enforces LF** for text, SVG and Python files, so a
   checkout cannot reintroduce CRLF.

Without the first, git's own normalisation *hides* the problem: the working
tree still looks clean after a rebuild even though the bytes on disk changed.
Give any new figure script the same explicit newline.

## Verifying it yourself

The claim above is checkable from a clean machine, and does not depend on
trusting this file:

```bash
git clone https://github.com/Azuromalachite/plasmid-ecoevo-lecture-2026
cd plasmid-ecoevo-lecture-2026
md5sum figures/output/shewanella-oxa48-pathway.svg
python figures/source/shewanella_oxa48_pathway.py
md5sum figures/output/shewanella-oxa48-pathway.svg   # same digest
git status --porcelain                               # no output
```

This check deliberately carries **no recorded digest to compare against**. The
two `md5sum` lines are compared with each other, and `git status --porcelain`
compares the rebuild against whatever commit the reader is standing on, so the
recipe cannot go stale.

An earlier version of this paragraph did name one — a commit and a digest,
"last checked" — and it drifted the first time the figure script changed, so
the file went on promising a digest the repository no longer shipped. A reader
following the recipe would have got a mismatch and concluded that determinism
had failed, when it had not. A digest written into prose is an unversioned copy
of a computation; the same defect class is recorded in
[`../docs/open-findings.md`](../docs/open-findings.md) under OF-5. The check
above is the version of it that has nothing to drift.

## Figures

### `size-copy-number-two-readings.svg`

Plasmid size against copy number, with a single power law and a segmented
pair of fits drawn over the same cloud.

- **Source:** [`source/size_copy_number_two_readings.py`](source/size_copy_number_two_readings.py)
- **Used by:** [`../concepts/plasmid-size-and-copy-number.md`](../concepts/plasmid-size-and-copy-number.md)
- **Status: illustrative, and the points are synthetic.** Every point is
  generated by a seeded linear congruential generator written out in the
  script. No dataset is plotted, no published point is reproduced, and the
  axis ranges are plausible rather than measured. It does **not** replace an
  empirical scaling-law figure and must not be captioned as one.
- **What is nonetheless honest about it:** both lines are least-squares fits
  to the points shown, computed in the script, so the contrast between one
  law and two regimes is a property of the drawn data rather than of hand
  placement. The pooled slope it reports is whatever the synthetic cloud
  gives and is deliberately not the published −0.65.
- **What the figure marks as open:** the model form itself, registry entry
  `claim.copy_number.size_scaling_form` in
  [`../evidence/claims.yml`](../evidence/claims.yml), an `interpretation`
  that is `not_tested`. The comparison between the two published studies is
  badged `NOT COMPARABLE` rather than `CONTESTED`, because they do not share
  a definition of copy number.

### `shewanella-oxa48-pathway.svg`

From an environmental *Shewanella* chromosome to a clinical IncL plasmid:
chromosomal context → Tn*1999* → pOXA-48 → new host and clinical spread.

- **Source:** [`source/shewanella_oxa48_pathway.py`](source/shewanella_oxa48_pathway.py)
- **Used by:** [`../case-studies/shewanella-oxa48.md`](../case-studies/shewanella-oxa48.md)
- **Status: illustrative, not calibrated.** No coordinate, length, copy number
  or frequency in the drawing comes from data. The plasmid circle has an
  arbitrary radius and no scale relationship to the chromosome line; the gene
  blocks are not to scale in either panel.
- **What *is* taken from sources:** the relative order of the genes *shown*
  flanking the chromosomal *bla*<sub>OXA-48</sub>-like gene in panel 1 follows
  Zong (2012); other reported neighbours (a peptidase ORF and *sprT*
  upstream, the acetyl-CoA carboxylase locus downstream) are omitted for
  legibility, so the panel is a subset of that neighbourhood rather than a
  complete map of it. The
  two-IS*1999* composite structure, the P<sub>out</sub> promoter, the IncL
  backbone and the Tn*1999* insertion into *tir* follow the references listed
  in the figure footer and cited in the case study.
- **What the figure deliberately marks as open:** the ancestral selective
  agent for the chromosomal gene (claim
  `claim.shewanella.oxa_ancestral_selection` in
  [`../evidence/claims.yml`](../evidence/claims.yml)).

### `copy-number-and-loss-rate.svg`

Segregational loss against **mean** copy number, with one curve per spread in
copy number across cells, drawn over the straight line the textbook formula
gives.

- **Source:** [`source/copy_number_and_loss_rate.py`](source/copy_number_and_loss_rate.py)
- **Status: analytic — no data and no fit.** This is a third badge, and it is
  not a softer version of either existing one. The other two figures are
  `illustrative` because their points are synthetic; this one has no points.
  Every value is computed by importing
  [`../models/copy-number-burden/battle_royale/segregation.py`](../models/copy-number-burden/battle_royale/segregation.py)
  by path, so the figure cannot drift from the model. Nothing is hand-placed
  — and nothing is measured either. **Do not caption it as evidence that real
  plasmids lose at these rates.**
- **What it is for:** `2**(-2c)` is steeply convex, so its average over a
  distribution of copy numbers is not its value at the mean. The low-copy
  tail carries essentially all of the loss. At a mean of 10 copies a CV of
  0.6 raises the rate about 2,100-fold; by a mean of 20 the gap is eight
  orders of magnitude. The figure exists so that "mean copy number" and
  "loss rate" are not spoken as if one determined the other.
- **The assumption that does the work:** copy number is taken to be lognormal
  across cells, matching the notebook's single-cell simulation. The left tail
  sets every value plotted, and a lognormal's left tail is the part it is
  least entitled to claim it got right. Read the vertical gaps as orders of
  magnitude, not as values.
- **What it deliberately leaves out:** partition systems, multimer
  resolution, clustering, conjugation and selection. A measured loss rate far
  **below** these curves is the expected result for a real low-copy plasmid,
  not a contradiction — active partitioning is what buys that distance.
- **Why the x axis starts at 3:** below about 3 copies the curve ordering
  reverses, because conditioning on carriers and the upward bias of rounding
  a skewed distribution to integers both outrun convexity there. Both effects
  are asserted in `segregation.self_check`, so the boundary is tested rather
  than described. Plotting that region would show crossings unrelated to the
  point being made.
- **Rendering note:** the three spread curves carry distinct
  `stroke-dasharray` values, but they are also separated by position and by a
  label at the end of each line, so the figure still reads in a renderer that
  drops dashes. PyMuPDF is one such renderer.

## Colour

[`source/palette.py`](source/palette.py) holds the shared palette and its
accessibility self-test. Run it:

```bash
python figures/source/palette.py
```

Two rules:

1. Colours stay distinguishable under simulated deuteranopia and protanopia.
   The self-test enforces this and fails loudly.
2. **Colour never carries meaning alone.** Every distinction is also carried
   by a label, shape, line style or position. Rule 1 limits the damage when
   colour fails; rule 2 is what makes a figure survive greyscale printing and
   a reader who sees no colour at all.

The module records two measured constraints rather than hiding them: COPY and
SPREAD are both blues because that is the only assignment of Okabe-Ito colours
to those three roles that clears the threshold under *both* simulations, and
the route and stage vocabularies share a colour because six Okabe-Ito colours
cannot supply two fully separable triples. A figure needing both must call
`check_union()`, which fails by design.

### The v0.1 figure predates this

`shewanella-oxa48-pathway.svg` uses its original colours, in which the brown
and the red collapse under deuteranopia (RGB distance 14; 36 under
protanopia). It is **not** being reissued: colour is not load-bearing there,
since the panels are numbered, titled and ordered left to right, so the figure
reads correctly in greyscale and under any colour vision. New figures use the
palette module.

## Conventions for new figures

1. One script per figure, standard library only where possible, deterministic
   output.
2. The figure states on its face whether it is **illustrative** or
   **calibrated**. A calibrated figure additionally names its data source,
   parameters and regime, either in the figure or in this file.
3. Source keys in the figure footer are BibTeX keys from
   [`../evidence/references.bib`](../evidence/references.bib).
4. SVG for diagrams. Raster output only when a figure genuinely needs it.
